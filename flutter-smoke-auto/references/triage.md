# 失败分诊

自愈环节最容易出的事故，是 AI 为了让测试变绿而不断放宽断言。放宽断言比测试失败危险得多——它把"没测"伪装成"通过"。这份规则的目的就是让"改测试"这个动作只在有明确证据时才被允许。

## 先查错位映射，再进判定顺序

Maestro 的错误信息经常指向错误的方向。分诊前先对这张表——实测每条都真实烧过时间：

| Maestro 报 | 常见真因（先查这个） |
|---|---|
| `Package X is not installed` | **设备选错了**（Android/iOS 模拟器共存时未显式指定 --udid/--device），不是没装。`run_smoke.sh` 已显式传，绕过它跑裸 maestro 时要自己传 |
| `Element not found: <id>` | **前一步没真的成功**（登录失败仍停在原页、弹窗挡住了）。先截图看当前在哪一页，再怀疑埋点 |
| `Couldn't hide the keyboard` | Flutter 自绘输入没有 dismiss action，删掉 `hideKeyboard` 这条命令 |
| 断言失败但截图看着"正常" | 静默问题：inputText 追加没清场、软键盘遮挡、预填数据。逐字段放大看截图里的实际值 |

配套纪律：**`Element not found` 时第一动作是截图确认当前页面**，不是检查 registry。
埋点错的概率远低于"流程根本没走到这一步"。

## 判定顺序

对每个失败，按顺序问，第一个命中的即为分类结果。

### 1. ENV_FLAKE — 环境问题

命中条件（任一）：
- 设备日志出现设备断连、adb offline、模拟器无响应
- Maestro 报错为超时且同一 flow 上一轮通过、本轮源码无相关改动
- 构建阶段失败（依赖拉取、签名、磁盘空间）

处理：原样重试一次。仍失败 → 降级为 APP_DEFECT 上报，不再重试。

### 2. TEST_DEFECT — 测试自身缺陷

命中需要**证据**，不能靠推测。允许改 flow 的三种情况：

| 症状 | 必需证据 | 允许的修改 |
|---|---|---|
| 元素找不到 | 契约表里该 id 对应的源码位置在本次 diff 中被改名/删除 | 更新为新 id |
| 断言过早 | 失败截图显示页面仍在过渡动画或 loading 中 | 加 `waitForAnimationToEnd` 或延长 timeout |
| 起始态污染 | 截图显示停留在上一条用例的残留页面 | 补 `clearState: true` |
| 元素在屏幕外 | 层级 dump 里存在该元素但不可见 | 改用 `scrollUntilVisible` |

拿不出对应证据 → 不属于这一类，往下走。

### 3. APP_DEFECT — 应用缺陷

默认归属。以下一定是这一类，**任何情况下都不允许通过改测试来消除**：

- 崩溃、ANR、白屏
- 接口返回非 2xx，或返回了但页面没渲染
- 业务断言不达成（该出现的数据没出现、该跳转的页面没跳）
- 数据未持久化
- 出现了错误提示文案

处理：写进报告缺陷区，附截图路径、设备日志相关片段、契约表指向的源码位置、复现步骤。测试保持红色。

**红色之后走哪条路，取决于功能是谁写的**：本次会话刚开发的功能 → 进入 SKILL.md
Phase 5.5 的修复闭环，修**功能代码**再重跑（改 lib/ 不受闸门限制，改测试才受限）；
既有 App 的存量功能 → 报告交用户决定，不擅自动存量代码。

## 禁止的"修复"

以下动作等同于伪造测试结果，任何时候都不做：

- 删除失败的断言
- 把 `assertVisible` 换成更宽松的匹配来绕过
- 把断言目标从业务元素换成一定存在的容器元素
- 给失败用例加 `optional: true` 或 `continueOnFailure`
- 延长 timeout 到 30 秒以上来"等到它出现"
- 把整条 flow 从测试集里移除

拿不准是 TEST_DEFECT 还是 APP_DEFECT 时，一律按 APP_DEFECT。误报一个 bug，用户看一眼就能否掉；漏报一个 bug，它会进生产。

## 自愈上限

每条 flow 最多改 3 轮。3 轮后仍失败，无论分类是什么，都按 APP_DEFECT 上报并停止自动修改——反复修不好本身就是信号，说明要么这个功能真有问题，要么这条用例的设计不合理，两种都需要人来看。

## 报告里的自愈记录

每次改 flow 都要记，格式：

```markdown
| flow | 轮次 | 分类 | 证据 | 改动 |
|---|---|---|---|---|
| smoke-02-login | 1 | TEST_DEFECT | login_submit_btn 在 commit a1b2c3 中改名为 auth_submit_btn | 更新选择器 |
```

这张表是给人复核用的。没有证据列的记录 = 未经授权的修改，应当被回退。
