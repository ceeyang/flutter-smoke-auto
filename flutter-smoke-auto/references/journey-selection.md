# 冒烟路径选择

## 通用判据

一条用例入选冒烟，要同时满足：

1. **发版阻断性** — 它挂了就不能发版。做不到这点的用例属于回归集，不属于冒烟。
2. **happy path only** — 不含边界值、异常分支、错误处理。冒烟回答"能不能用"，不回答"健不健壮"。
3. **90 秒内** — 单条超时说明步骤太长，拆或砍。
4. **状态独立** — 不依赖上一条留下的数据。每条 `clearState: true` 重来。

总量 5–8 条，整套 5 分钟内。这不是保守，是冒烟的定义：它要在每次提交后都跑得起，跑不快就没人跑。

## 优先级排序

按"坏了影响多少人"排，不按"实现多复杂"排：

1. **冷启动** — App 能起来、不白屏、不闪退。这条永远排第一，因为它挂了后面全部无意义
2. **身份** — 登录/注册/退出。绝大多数功能的前置
3. **核心价值动作** — 用户来这个 App 到底为了干什么，那一件事
4. **主导航** — 底部 tab / 抽屉能全部切到，不崩
5. **数据持久** — 关键数据杀进程重启后还在
6. **收入路径** — 涉及支付/订阅的入口能打开（不真实付款，到收银台即可）

## 按 App 类型的模板

**内容/社区类**（评价平台、社交、资讯）
冷启动 → 登录 → 首页信息流有内容 → 打开详情 → 发布一条 → 搜索出结果 → 退出登录

**电商类**
冷启动 → 登录 → 搜商品 → 进详情 → 加购物车 → 进结算页（止步于此，不真付） → 看订单列表

**工具类**（无账号体系）
冷启动 → 主功能执行一次 → 结果正确渲染 → 数据持久化验证 → 设置页可达

**IM 类**
冷启动 → 登录 → 会话列表加载 → 进会话 → 发一条消息 → 消息出现在列表

## 明确排除

这些不放进冒烟，放进去只会拖慢并制造 flaky：

- 短信/邮件真实验证码（用编译期测试后门固定值，或干脆跳过登录直接注入 token）
- 真实支付
- 推送通知（依赖外部服务，时序不可控）
- 相机、相册、蓝牙、定位等硬件权限流
- 依赖服务端特定数据状态的流程（除非有可控的种子数据接口）
- 任何需要等待超过 10 秒的异步任务

## 定向用例的自包含要求

定向验证（`--changed` / `--only`）跑的是整条用例而不是单个步骤，所以**前置到达链是用例的一部分，不是可省略的上下文**。"只测上传头像"的用例必须自己走完到达路径：

```yaml
- launchApp: { clearState: true }        # 起点永远是干净冷启动
- runFlow: { file: ../subflows/login.yaml }   # 前置抽成 subflow 复用，不复制粘贴
- tapOn: { id: "mine_tab" }              # 导航到达
- tapOn: { id: "profile_avatar_btn" }    # 才轮到被测功能
- ...断言
```

生成新定向用例时自查一句：**"这条用例在刚装好的干净设备上能独立跑通吗？"**不能就是漏了前置。

登录这类公共前置一律 `runFlow` 引 subflow。select_flows 也认这条链：改了登录页，所有引用 login subflow 的用例都会被自动圈进来，这是正确的扩散。

到达链太长拖慢定向验证时，用 deep link 直达或 `SMOKE_TEST` 编译开关注入测试 token 缩短前置（token 注入见 vision-fallback），但断言部分不变。

## 写进 plan.md 的格式

每条用例必须能回答"它挂了意味着什么"。答不上来的用例，说明不该在冒烟里。

```markdown
### SMOKE-03 发布一条评价
- 目的: 验证核心价值动作（写评价）端到端可用
- 前置: 已登录测试账号 ${TEST_PHONE}
- 步骤: 首页 → 商家详情 → 写评价 → 填标题正文评分 → 提交
- 断言:
  - 到达: 评价详情页锚点 review_detail_title 可见
  - 无错: 无错误提示文案
  - 持久: 返回商家页，新评价出现在列表首位
- 失败意味着: 用户无法产生内容，产品核心失效，阻断发版
- 依据: docs/prd-review.md L45-52
```
